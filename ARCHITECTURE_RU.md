# Архитектура и спецификация asyncTelegramAPI

📖 **[English version](ARCHITECTURE.md)**

## 1. Введение и назначение проекта

**asyncTelegramAPI** — легковесная, полностью неблокирующая библиотека Telegram Bot API для микроконтроллеров **ESP8266** и **ESP32**, работающих через **Wi-Fi**.

Библиотека разработана с нулевой зависимостью от сторонних сетевых библиотек (Zero-dependency networking). Она использует встроенные системные защищенные клиенты (`BearSSL::WiFiClientSecure` на ESP8266 и `WiFiClientSecure` на ESP32) и управляется быстрым неблокирующим конечным автоматом (FSM) с поддержкой HTTP Keep-Alive и фоновых задач FreeRTOS на ESP32.

### Ключевые преимущества:
- **Zero External Network Dependencies:** Никаких сторонних сетевых библиотек (`AsyncTCP`, `ESPAsyncTCP`). Только стабильные системные сокеты и `ArduinoJson ^7.0.0`.
- **Zero-blocking FSM:** Шаг автомата `bot.tick()` в цикле `loop()` выполняется менее чем за 1 микросекунду при отсутствии входящих данных, оставляя процессор на 100% свободным для датчиков, кнопок и дисплеев.
- **ESP32 FreeRTOS Task Mode:** Опциональная фоновая задача на втором ядре (`AsyncTelegramAPI bot(true);`), полностью освобождающая от вызова `bot.tick()` в `loop()`.
- **Tx FIFO Outbox Queue:** Очередь до 32 исходящих пакетов с приоритетом над входящим поллингом.
- **Smart Interactive Window:** Редкий short-polling в покое (с закрытием сокета и освобождением памяти) и автоматическое пробуждение в быстрый Long Polling при входящих командах.
- **Auto HTML & Menu:** Автоопределение разметки `</` и клавиатуры `[MENU]`.
- **Supergroup Topics & Edit Message:** Поддержка тем (`threadId`) и редактирование сообщений по ID с callback подтверждения доставки.
- **RAM & Flash Optimization:** Строгий перенос строк в PROGMEM (`F()`, `PSTR()`) и полное вырезание отладочного кода при отключении `#define DEBUG`.

## 2. Эволюция архитектуры и отказ от сторонних AsyncTCP библиотек

На начальном этапе проектирования рассматривался вариант использования сторонних библиотек асинхронных сокетов (`AsyncTCP` для ESP32 и `ESPAsyncTCP` для ESP8266). Однако в ходе практического анализа и стресс-тестирования был выявлен ряд критических фундаментальных проблем:

1. **Нестабильность TLS/SSL в AsyncTCP:**
   Telegram Bot API работает исключительно по защищенному протоколу HTTPS (порт 443). В сторонних библиотеках `AsyncTCP` / `ESPAsyncTCP` поддержка TLS реализована через экспериментальные или форкнутые обертки. Они страдают от утечек памяти при переподключениях, фрагментации кучи и периодических аварийных сбоев (Kernel Panic / Watchdog Reset).
2. **Конфликты версий и окружения:**
   `ESPAsyncTCP` и `AsyncTCP` часто конфликтуют с обновлением версий ядра Arduino (ESP-IDF 4.x/5.x и ядро ESP8266 3.x), требуя ручных патчей и затрудняя установку.
3. **Исчерпание дескрипторов сокетов (Socket Exhaustion):**
   При частом закрытии и открытии асинхронных TCP-дескрипторов сокеты зависают в состоянии `TIME_WAIT` (до 60 секунд), блокируя сетевой стек lwIP.

### Выбранное решение: Неблокирующий FSM + Keep-Alive + FreeRTOS
Вместо добавления ненадежных сторонних сетевых библиотек, архитектура построена на базе:
- Системного **`BearSSL::WiFiClientSecure`** (на ESP8266 с лимитированными буферами 1024/512 для экономии RAM).
- Системного **`WiFiClientSecure`** (на ESP32).
- Неблокирующего конечного автомата (FSM), пошагово опрашивающего `client.available()`.
- Постоянного соединения **HTTP Keep-Alive**, исключающего затраты времени и памяти на повторные TLS-рукопожатия.
- На ESP32 — опционального воркера FreeRTOS (`xTaskCreatePinnedToCore`), изолирующего работу с сетью от пользовательского кода.

## 3. Архитектура слоев (Layered Architecture)

```
+-------------------------------------------------------------+
|                        User Sketch                          |
|         setup(), loop() [полностью свободен], callback()    |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|                      AsyncTelegramAPI                       |
|   - start() / stop() / tick() / checkMessage()              |
|   - sendMessage(), editMessage(), deleteMessage()           |
|   - Tx FIFO Queue (Очередь сообщений с приоритетом)         |
|   - Interactive Window & Polling Timer                      |
|   - FreeRTOS Task Worker (ESP32)                            |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|                        TelegramCore                         |
|   - Структура TResult (с поддержкой threadId топиков)       |
|   - Формирование JSON для getUpdates, sendMessage...        |
|   - Парсинг ответов Telegram API (ArduinoJson 7)            |
|   - Парсер меню [MENU], whitelist, is_command               |
+-------------------------------------------------------------+
                              |
+-------------------------------------------------------------+
|                 Системный сетевой уровень                   |
|     ESP32: WiFiClientSecure   |   ESP8266: BearSSL          |
|                 (TLS 1.2 / системный lwIP)                  |
+-------------------------------------------------------------+
```

## 4. Состояния конечного автомата (FSM)

Автомат `AsyncTelegramAPI` работает без блокирующих задержек (`delay()`), переключая состояния по мере готовности данных в сокете:

```
                  +-------------------+
                  |      TG_IDLE      |<-----------------------+
                  +-------------------+                        |
                     |  |                                      |
       (есть Tx в    |  | (наступило время                     |
        очереди)     |  |  опроса poll)                        |
                     v  v                                      |
         +----------------------+                              |
         |   _ensureConnected   |                              |
         | (TLS handshake 443)  |                              |
         +----------------------+                              |
                     |                                         |
                     v                                         |
         +----------------------+                              |
         |   _sendHttpRequest   |                              |
         | (POST /bot... json)  |                              |
         +----------------------+                              |
                     |                                         |
                     v                                         |
         +----------------------+                              |
         |     TG_WAIT_DATA     | (Срочный Tx прерывает poll!) |
         +----------------------+                              |
                     | _client.available() > 0                 |
                     v                                         |
         +----------------------+                              |
         |   TG_READ_HEADERS    |                              |
         | (построчный парсинг) |                              |
         +----------------------+                              |
                     | найдена пустая строка \r\n            |
                     v                                         |
         +----------------------+                              |
         |     TG_READ_BODY     |                              |
         | (чтение Content-Len) |                              |
         +----------------------+                              |
                     | получено все тело                       |
                     v                                         |
         +----------------------+                              |
         |  _parseResponseBody  |                              |
         | (вызов user callback)|                              |
         +----------------------+                              |
                     |                                         |
                     +-----------------------------------------+
```

1. **TG_IDLE:** Состояние покоя. Проверяется очередь исходящих сообщений (`_txQueue`) и таймер опроса входящих (`readyToPoll`).
2. **_ensureConnected:** Проверка соединения. Если сокет закрыт — устанавливается защищенное TLS-соединение с `api.telegram.org:443`.
3. **_sendHttpRequest:** Неблокирующая отправка HTTP POST пакета (метод API, токены, заголовки Keep-Alive/Close, тело JSON).
4. **TG_WAIT_DATA:** Пассивное ожидание ответа от сервера:
   - Если сервер держит Long Polling — автомат ждет данные.
   - **Срочная отправка:** Если пользователь поставил в очередь исходящее сообщение во время Long Polling, сокет мгновенно сбрасывается для немедленной отправки Tx!
5. **TG_READ_HEADERS:** Построчное чтение HTTP-заголовков. Извлекаются код ответа (`HTTP/1.1 200 OK`) и заголовок `Content-Length`.
6. **TG_READ_BODY:** Потоковое наполнение буфера тела до достижения `Content-Length`.
7. **_parseResponseBody:** Десериализация JSON через ArduinoJson 7:
   - Если это ответ на отправку Tx — вызов callback `onSent(messageId)`.
   - Если это `getUpdates` — извлечение массива `updates`, проверка `strict` / `whiteList`, продление интерактивного окна и вызов пользовательского `callback(TResult)`.
   - Если в очереди есть еще сообщения — переход к следующему Tx, иначе сокет удерживается открытым при Long Polling или мягко закрывается при Short Polling.

## 5. Зависимости и структура файлов библиотеки

### Зависимости:
- **`bblanchon/ArduinoJson @ ^7.0.0`** — единственная внешняя зависимость.

### Структура файлов:
```
asyncTelegramAPI/
├── library.json           // Манифест PlatformIO
├── library.properties     // Манифест Arduino IDE Library Manager
├── README.md              // Подробная документация и описание API
├── ARCHITECTURE.md        // Архитектурная спецификация FSM
├── src/
│   ├── AsyncTelegramAPI.h // Основной неблокирующий класс бота
│   └── TelegramCore.h     // Структура TResult, утилиты меню и JSON
└── examples/
    ├── Basic_Bot/         // Базовый универсальный пример для loop()
    ├── ESP32_FreeRTOS/    // Фоновый режим на отдельном ядре ESP32
    └── Interactive_Dashboard/ // Пример дашборда с editMessage и callback
```
